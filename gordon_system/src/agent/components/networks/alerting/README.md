# AlertingNetwork

Gordon's exogenous attention-demand coordination Network.

## Overview

The **AlertingNetwork** is Gordon's implementation of **exogenous attention**:
the detection and estimation of attention demand generated by changes, signals,
events, and deviations that originate outside the agent's currently directed
attentional objective.

```text
AlertingNetwork = exogenous attention demand assessment
FocusingNetwork = endogenous attention commitment (future)
```

## Canonical Definition

> The AlertingNetwork is Gordon's exogenous-attention coordination Network,
> responsible for transforming externally originating or unexpectedly emerging
> signals into structured, explainable, bounded assessments of attentional
> demand.

### Questions Answered

The AlertingNetwork answers:

```text
What unexpected, changing, urgent, intense, novel, or contextually significant
signal is currently requesting attention?
```

It does **NOT** answer:

| Question | Belongs To |
|----------|-----------|
| What should Gordon deliberately focus on? | Future `FocusingNetwork` |
| Which signal ultimately wins? | Executive/Arbitration |
| Should the current Thread be interrupted? | Executive/Core |
| What does this percept mean? | Perception/Cognition |
| What should Gordon do? | Planning/Action |

## Alerting vs Focusing

| Aspect | AlertingNetwork | FocusingNetwork (future) |
|--------|-----------------|-------------------------|
| Direction | signal → agent | agent objective → selected representation |
| Cause | unexpected or externally originating demand | goal, intention, plan, commitment |
| Primary question | What is requesting attention? | What should remain selected and protected? |
| Typical evidence | sudden change, novelty, prediction error, urgency | active objective, current task, working-memory target |

### Separation of Concerns

```text
AlertingNetwork
    └─ estimates exogenous attention demand (external)
    
FocusingNetwork  
    └─ estimates endogenous attention commitment (internal)

Executive/Arbitration
    └─ resolves competition between the two
```

## Neuroscience Rationale (Brain-Agnostic Translation)

Biological attention systems use two complementary mechanisms:

1. **Externally driven reorientation** - Detect when a signal's significance
   may exceed the value of continuing current focus. This requires rapid change
   sensitivity, novelty detection, and urgency assessment.

2. **Internally maintained selection** - Maintain attention on currently
   selected objectives despite distraction.

Gordon implements these as:

- `AlertingNetwork` for exogenous demand estimation
- `FocusingNetwork` for endogenous commitment maintenance

The separation is essential: **detection ≠ authorization**. A signal may request
attention without winning it.

## Public API

### Core Contracts

| Symbol | Description |
|--------|-------------|
| `AlertingInput` | Canonical input contract for assessment |
| `AlertingAssessment` | Immutable output with demand score, level, recommendation |
| `AlertingContext` | Optional context that modulates demand |
| `AlertingFeatures` | Computed features for explainability |
| `AlertingReason` | Individual reasons contributing to assessment |
| `AlertingProvenance` | Traceability metadata |

### Enums

| Symbol | Description |
|--------|-------------|
| `AlertingModality` | Signal modality (visual, auditory, etc.) |
| `AlertingSource` | Signal origin (perception, memory, system) |
| `AlertingLevel` | Demand classification (NEGLIGIBLE, LOW, MODERATE, HIGH, CRITICAL) |
| `AlertingRecommendation` | Advisory recommendation (IGNORE, OBSERVE, REQUEST_ATTENTION, etc.) |

### Protocol

```python
class AlertingNetworkProtocol:
    def assess(alerting_input: AlertingInput) -> AlertingAssessment
    def snapshot_state() -> AlertingNetworkStateSnapshot
    def reset(reset_request: AlertingResetRequest) -> AlertingNetworkStateSnapshot
```

## Input Model: AlertingInput

```python
AlertingInput(
    signal_id: str,
    source: AlertingSource,        # Origin of the signal
    modality: AlertingModality,    # Sensory channel
    timestamp: datetime,           # When observed (not generated!)
    
    # Primary features
    intensity: Optional[float],    # Signal strength (0.0 to 1.0)
    previous_intensity: Optional[float],
    background_intensity: Optional[float],
    
    # Event flags
    onset: Optional[bool],
    offset: Optional[bool],
    change_detected: Optional[bool],
    
    # External hints (provided by other systems)
    novelty_hint: Optional[float],
    urgency_hint: Optional[float],
    prediction_error: Optional[float],
    
    # Context (owned by caller)
    context: Optional[AlertingContext] = None,
    
    provenance: Optional[AlertingProvenance] = None
)
```

## Output Model: AlertingAssessment

```python
AlertingAssessment(
    assessment_id: str,
    signal_id: str,
    
    # Core values
    demand_score: float,      # 0.0 to 1.0
    confidence: float,        # 0.0 to 1.0
    
    # Classification
    level: AlertingLevel,               # NEGLIGIBLE, LOW, MODERATE, HIGH, CRITICAL
    recommendation: AlertingRecommendation,
    
    # Features for explainability
    features: AlertingFeatures,
    modulation: AlertingModulation,
    reasons: Tuple[AlertingReason, ...],
    
    provenance: AlertingProvenance
)
```

### Assessment Levels

| Level | Score Range | Meaning |
|-------|-------------|---------|
| NEGLIGIBLE | 0.0 to <0.1 | Below threshold; no attention needed |
| LOW | 0.1 to <0.3 | Minor deviation; observation sufficient |
| MODERATE | 0.3 to <0.5 | Noticeable deviation; consider attention allocation |
| HIGH | 0.5 to <0.8 | Significant deviation; allocate attention soon |
| CRITICAL | 0.8 to 1.0 | Extreme deviation; demand immediate attention review |

### Recommendations

| Recommendation | Meaning |
|----------------|---------|
| IGNORE | No attention needed |
| OBSERVE | Monitor, no action yet |
| ELEVATE | Warrants elevated priority |
| REQUEST_ATTENTION | Allocate some attention resources |
| REQUEST_URGENT_ATTENTION | Demand immediate attention review |

## State Model

The AlertingNetwork owns only **bounded computational state**:

- Temporal baseline statistics (recent signal history)
- Habituation state (response attenuation with repetition)
- Refractory state (recovery period after recent alerts)
- Diagnostic counters

It does **NOT** own:
- Cognitive goals
- Active task state
- Full perceptual history
- Global event history

## Architecture Invariants

All implementations must satisfy:

| Code | Invariant |
|------|-----------|
| ALERT-INV-001 | AlertingNetwork produces advisory assessments only |
| ALERT-INV-002 | AlertingNetwork never authorizes interruption |
| ALERT-INV-003 | AlertingNetwork never schedules execution |
| ALERT-INV-004 | AlertingNetwork never maintains endogenous focus |
| ALERT-INV-005 | AlertingNetwork state is bounded computational state |
| ALERT-INV-006 | AlertingNetwork accepts immutable projected input |
| ALERT-INV-007 | AlertingNetwork returns immutable assessment output |
| ALERT-INV-011 | Alerting and Focusing remain separate authorities |

## Anti-Patterns

Do **NOT**:

- Use `ExogenousAttentionNetwork` as an alias
- Import legacy alerting code
- Make AlertingNetwork responsible for endogenous focus
- Authorize interruption directly from AlertingNetwork
- Schedule execution or change runtime state
- Route arbitrary events or commands
- Create unbounded state structures
